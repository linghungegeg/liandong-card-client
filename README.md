# 链动卡密客户端

## 范围与界面

只做链动卡密商品：多账号隔离、商品读取与发布、手动加卡、本地 TXT/XLSX/CSV 来源、库存监控和自动补卡。排除知识、资源、权益，以及订单、营销、分销、资金、云同步等其他业务。

界面按链动官方布局、配色、字段和操作顺序实现。每个功能独立一级栏目，不做嵌套菜单；协议优先，不用模拟鼠标点击执行发布或补货。

| 一级栏目 | 职责                                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------------------------- |
| 仪表盘   | 当前/全部账号的登录状态、商品/平台库存、监控任务、待确认/失败任务、近期补货结果；全部来自真实数据，区分未同步与零值 |
| 账号管理 | 添加、登录、切换、会话状态；账号官网入口                                                                            |
| 卡密商品 | 官方风格商品表格、筛选、商品/库存读取                                                                          |
| 商品发布 | 官方卡密商品字段、图片及价格，协议发布                                                                        |
| 手动加卡 | 商品、粘贴或文件来源、预览、协议提交                                                                           |
| 卡密来源 | TXT/XLSX/CSV 工作表和列选择，绑定账号/商品，保留原文件                                                         |
| 库存监控 | 独立开关、低库存阈值、固定补货量或目标库存、检查间隔                                                                |
| 补货记录 | 手动/自动共用批次记录，确认成功/失败/待确认及错误原因                                                               |

打开官网是全局按钮，不是另一套业务管理功能。

## 技术边界

- Electron + React + 本地 SQLite，不加入 Python 服务或远程业务后端。
- 参考懒人铺货迁移分支：每账号一个默认隐藏 BrowserWindow，使用独立持久化 partition。
- 官方页面承担登录/验证和请求上下文，日常操作在本客户端完成。协议请求在对应账号网页环境内发起，复用其登录态、UA、请求头及官方必要封装。
- 打开官网显示原账号窗口，关闭查看时隐藏；退出软件释放资源。首次登录/人工验证才显示窗口；登录失效暂停对应补货。
- 账号、商品、来源、规则和卡密记录按账号隔离。官方当前卡密发布/加卡表单没有独立规格字段，因此直接绑定官方商品 ID，不新增规格机制。分区隔离不等于伪造不同硬件指纹。
- 不关闭 webSecurity，不为远程页面开启 Node.js；前端 IPC 只暴露限定业务能力。
- Cookie/Token/密码不写普通配置文件、日志、README 或前端持久化。

## 补货约束

1. 平台可售库存和本地待上传卡密分别统计；按官方商品 ID 绑定。
2. 库存严格低于阈值才触发，每条规则选择固定补货量或补到目标库存。
3. 手动/自动共用加卡协议、批次记录和结果核实流程。
4. 本地卡密按未使用、预留/待确认、确认已上传管理；原文件不变，保留前导零，不静默改变有效内容。
5. 同一账号、商品串行处理，提交前再读库存。
6. 超时/断网/进程中断不等于失败；不确定批次在核实前不重传或释放卡密。
7. 用官方响应和卡密记录核实接收数量；库存增量不能作为唯一成功证明。
8. 文件不足、登录/商品失效或结果不明时暂停受影响任务并显示原因。停止监控不再发起新提交，已发出请求继续核实。

## 分阶段执行与验收

### 阶段 0：协议与官方规则

核对商品列表/详情/库存、发布字段/图片上传、加卡、回读与鉴权。通过只读页面和已加载脚本确认，不猜接口，不为探测擅自发布商品或上传卡密。每条链路明确实际观察、静态候选、未验证项和成功判据。

### 阶段 1：桌面与账号

完成全部一级栏目、仪表盘基础、受限 IPC、独立持久化账号、隐藏页面、登录与官网窗口、同环境协议入口。验收多账号归属、重启恢复、失效提示、敏感日志排除，以及页面/请求身份一致性。

### 阶段 2：卡密商品与发布

完成列表/库存、官方卡密发布表单及协议。验收数据与官方一致；失败保留内容并明确原因；发布成功具备响应与回读。真实发布使用用户指定内容并在执行前确认，不擅自上架。

### 阶段 3：来源与手动加卡

TXT 一行一条；XLSX/CSV 文本解析、工作表/列选择；预览空行、重复和有效量。账号/商品绑定、使用记录、协议加卡、结果核对。验收重复导入/重启不重传，部分成功/不确定结果明确；真实测试卡密执行前确认。

### 阶段 4：自动补卡

定时读取、阈值判断、提交前复检、卡密预留、共用加卡及核实。验收阈值边界、串行、多账号独立、停止、断网、失效和恢复不重复提交。

### 阶段 5：复检与交付

相关单测、静态安全检查、构建、Windows 启动、隐藏/显示和数据恢复。仪表盘统计真实数据，区分平台库存、本地卡密、成功和待确认结果。分开报告源码/测试、真实页面/网络、真实发布/加卡验收；未实测不标完成。每阶段闭环复检后推进，不擅自部署或推送。

## 使用方式

- 本轮使用开发环境：在项目目录执行 npm run dev:desktop，打开“链动卡密客户端”桌面窗口。默认数据保存在系统应用数据目录；可通过 LIANDONG_DATA_DIR 指定隔离测试数据目录。旧便携包未包含本轮修复。
- 添加账号后，在客户端输入官方账号与密码登录；需要人工验证时用“打开官网”。密码只用于本次请求，凭据保留在官方账号分区，客户端数据目录为系统用户的应用数据目录。
- 同步商品，在“卡密来源”选择商品并导入文件；确认预览后入本地来源。Excel 卡号/密码建议使用文本单元格；Excel 已经丢失的前导零无法还原。
- “手动加卡”选择绑定来源和数量提交；“库存监控”设置阈值、目标或固定数量、间隔，保存后单独启用。
- 导入的是文件内容快照，原文件不修改。后续文件增加内容，需要重新选择并导入；已存在卡密按同一账号去重。应用正常退出/重启后保留规则与使用记录。
- 写入结果不明时不要重复提交，进入“补货记录”重新核实；无法唯一匹配则继续待确认。关闭主窗口会退出软件并停止监控，不会留隐形进程持续补货。

## 开发验证

在项目目录执行 npm install、npm run check、npm test。npm run dev:desktop 同时启动本机 Vite（http://127.0.0.1:5188）和 Electron 桌面客户端，关闭客户端后停止开发服务。业务测试在桌面窗口进行，单独浏览器预览不具备账号会话和 IPC 能力。前端修改通过开发服务更新；修改 electron/ 下的主进程文件后需要重启开发客户端。

npm run build 仅构建前端资源，不生成运行包。npm run package 用于后续另行确认的 Windows 运行包交付，本轮不执行。

生产构建有前端单块超过 500KB 的提示，目前构建及运行通过。现阶段不扩展自动更新、安装程序、订单等范围外功能。
